# 功能开关验收记录

## Android 67 / Mac 30 / 中继 4（2026-10-05）

用户授权整体整改、验证与部署，并明确总开关关闭时暂停后台功能、同步及远程访问，同时保留子开关、配对与配置。源码保留在 main 工作区，未提交、未推送；工作区原有的安全改动一并保留，没有还原或覆盖。

### 检查结论与整改

| 原问题 | 当前设计 |
| --- | --- |
| 选择、系统权限、远程授权混在一起 | 手机总开关与功能选择、系统就绪条件、远程访问范围分开保存和呈现 |
| 缺权限时开关被禁用，无法先表达选择 | 开关保存用户意图；开启时检查缺项并提供设置入口，拒绝或稍后处理仍保留选择 |
| 缺少整体暂停入口 | 手机首页总开关停止后台与远程接入，结束应用持有的控件与会话；恢复原偏好，不补执行旧操作 |
| 两个通知方向缺少独立控制 | 手机通知 → Mac 与电脑提醒 → 手机各自有子开关，横幅和铃声仍为显示设置 |
| 功能入口与权限入口分散 | 手机集中功能页分三组，Mac 提供功能状态页；原远程授权页改名为远程访问范围 |
| 本地 adb 入口可能绕过应用内选择 | Mac 按钮与随包脚本读取手机投射状态；录屏和持灯进程持续检查并正常停止 |
| 关闭功能后 CLI 误报旧版工具不全 | Shell / 安装在提交前提示具体关闭功能；远程访问拒绝仍单独提示 |
| 无条件申请权限、无关权限计为故障 | 明确开启时检查相关权限；恢复总开关时汇总检查；关闭功能不计为权限缺项 |

执行层同时检查功能选择和原远程授权，直接工具名、批量、文件锁后和特权服务绑定后再次检查。关闭开关使旧连接请求失效，不能借重新开启继续执行旧请求。中继只承载请求和保留回执，不承担手机功能选择或系统授权。

### 真机与视觉边界

仅在荣耀 PGT-AN20 / Android 15 验证。候选实测关闭电脑提醒子开关，空提醒请求在执行前被拒绝，手机通知同步仍保持开启；恢复后均就绪。总开关关闭后 Keeper / MCP 服务停止、远程初始化不能到达手机，adb 保留恢复途径，Mac 本地功能按钮禁用；重新打开后本地和远程恢复。原剪贴板 shared / automatic / images、通知接收和应用选择数量、六项远程授权均与升级前一致，受控测试结束时 11 项子开关保持原选择；之后复查发现 Shell 子开关已关闭，保留现场最新选择。安装版 CLI 的只读预检准确提示此子开关已关闭，不上传、不提交安装或执行 shell。

手机原生首页和功能页已检查，最终 Android 67 首页也已检查。录屏停止验证期间手机前台切到其他应用，未继续点击其他应用；完整的总开关中途停止实测等待手机保持在手机工位首页。Mac 实际面板自动读取超时，使用同一 SwiftUI 源码原生离屏渲染检查首页、功能页、通知被拒绝仍保持接收选择的状态及浅色/深色布局；不将离屏渲染称为实际菜单栏面板截图。

录屏启动与 TERM 正常收尾的真实 MP4 结构已检查。停止测试发现后台子进程继承忽略 INT 的状态，新增回归可以复现旧实现；Mac 30 在 exec 前恢复信号处理，先给录屏正常收尾时间，再对不响应的进程进行有界清理并明确提示可能不完整。模拟回归分别覆盖正常收尾和忽略 INT / TERM 的异常进程；本轮没有将未完成的真机总开关录屏测试标为通过。

未撤销真机既有系统权限或替用户改变通知使用权及应用白名单；缺权限、拒绝后保留开关的行为以源码、Java / Swift / Python 回归和原生状态渲染核验。手机重启、其他机型及长时间网络切换未在本轮新增验收。已获准的外部 adb / Shizuku 系统能力不能由应用开关撤销，具体边界见 [功能开关](../features.md)。

完整构建、安装与服务回执位于本机忽略目录 `build/.phone-station/feature-deployment/final/`，其中 `acceptance.json` 分别记录源码、测试、构建、部署和恢复；构建清单的 deployed:false 保留原含义，由独立安装回执记录实际部署。
