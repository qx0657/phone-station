Android 67 / Mac 30 增加独立的总开关与功能子开关，系统权限、功能选择和远程访问范围分开保存，见 [功能开关](features.md)。下文保留分项远程授权的安全边界；当前页面名称为「远程访问范围」。

# 远程连接的安全与授权

Android 64 起，配置远程中继只建立连接，默认仅开放设备、控件、Shizuku 和通知同步的状态查询，以及结束已有投屏、终端的工具。Android 65 起在手机「权限与检查 → 远程权限」按需开启能力，远程通道页保留摘要和入口，保存过的中继资料默认折叠。Android 64 的入口仍在「MCP 服务 → 远程通道」内。Mac、配对广播和 MCP 请求不能直接授予这些权限。

## 手机端权限

| 手机开关 | 开放范围 |
| --- | --- |
| 文件读取 | 普通文件的列表、stat、文本/字节读取、搜索、存储概况 |
| 文件修改 | 创建、覆盖、追加、补丁、截断、复制、移动、永久删除普通文件 |
| 剪贴板与通知 | 剪贴板读取、写入和同步配置；接收手机上已选应用的通知、图标及同步配置 |
| 手机控件与提醒 | 截屏及截图查询/释放、打开文件、亮屏、手电筒、会话提醒 |
| 投屏与操控 | 经中继查看屏幕、收听手机音频、录屏和输入操控 |
| Shell 与安装 | Shizuku 单次命令、后台 shell、交互终端和 APK 安装 |

权限独立，没有隐式继承。APK 安装仍通过 shell 上传助手执行，一般还需文件读取和文件修改；远程截屏下载需要文件读取。投屏开关也保护从本地 MCP 发起的中继屏幕会话，因为其画面和输入仍经过公网中继。本地 adb 的普通文件、shell 和 scrcpy 保留原权限方式。

Mac 27 在投屏、截屏、控件、剪贴板、通知、命令和安装入口显示具体缺项与「去授权」。安装和截图下载分别检查完整权限组合，未通过时不上传、提交或创建截图；原安装任务只需 Shell 权限查询，并保留编号。CLI 安装检查遇到手机权限拒绝返回 1，不把它当离线而回退 adb。手机已开启的剪贴板和通知功能在仅远程连接且缺少授权时也显示处理入口，共用一项权限的影响不重复计数。默认关闭的能力不批量算作权限故障。

授权入口只定位手机上的权限项，不修改选择；只有已连接本地 adb 时 Mac 可打开手机页面。返回后只刷新状态，安装、命令和截屏必须重新点击；同步恢复先建立新基线，不发送先前的数据。升级 64 到 65 保留已有授权，不再次清空开关。

未知工具默认拒绝；工具列表按手机权限过滤，直接猜工具名同样受限。批量调用先检查所有工具的权限，整批通过后才执行。任务结果查询根据原任务类型检查对应权限，投屏权限不能用来读取 shell 或终端任务输出。

关闭远程通道、更改权限或更换中继资料会撤销旧客户端的执行资格。排队任务在文件锁、特权服务绑定等待之后再次检查，不能在重新连接后借用新权限继续启动。正在使用的中继屏幕结束；远程客户端登记的终端被关闭，不主动关闭其他本地终端。操作编号和原回执保留，不把取消当作重新执行的许可。已经发给系统的 shell、安装或文件操作无法撤回，可能继续完成，须按原编号核实结果。

更换服务器地址、证书指纹，或重新填写手机令牌，会清除全部远程授权。原地址与指纹不变且令牌留空时保留授权。仅关闭、重新打开远程通道保留开关选择。手机配置页禁止屏幕捕获，已保存令牌不回填。

## 网络与身份边界

手机 MCP 只监听手机回环，Mac 网关只监听电脑回环，不暴露 adb。两端远程连接必须使用 HTTPS/WSS、固定 SPKI，并分别使用手机和电脑角色令牌；不自动跟随重定向。本机 HTTP 工具调用、探测和 Mac 状态读取也拒绝重定向，避免转发 Bearer 或重发操作。

公网中继 4 拒绝浏览器 Origin、多个 Authorization、URL 凭据、重复操作查询参数，以及含重复 JSON 字段、无效 UTF-8、过深嵌套或尾随正文的请求。错误响应和正常结果均禁止 HTTP 缓存。重复字段检查包括转义后的同名键、请求负载和结果正文；不允许不同组件把同一请求解释为不同操作。持久编号与结果恢复继续使用 [中继合约](relay-contract.md)，屏幕消息仍有大小、角色和时限限制。

中继 5 的控制与事件连接延续上述身份与来源校验。控制 WSS 使用手机角色，事件 WSS 使用电脑角色；本机事件入口仅接受完整网关身份，受限客户端不可访问。事件只有主题与订阅编号，正文仍走原有工具授权；订阅只能续租已有的同 clientId 会话，不能开启功能、代替系统授权或建立内容基线。断线、取消、配置与权限变化后的租约边界见 [远程控制与事件](remote-control.md#通知与剪贴板订阅)。

Mac 的 [受限客户端令牌](mcp-clients.md) 是额外的一层权限；经公网转发时还必须满足手机开关。不要将 Mac 主令牌交给只需要读取文件的客户端。

## 信任范围与部署

现有中继仍能读取请求、结果、画面和输入；协议没有独立的端到端签名或加密。中继被攻破、角色令牌泄露或可信电脑被恶意程序控制后，攻击者仍可能使用手机已开启的能力。手机端默认拒绝能限制影响范围，但不能把已经授予 Shell 的连接变成安全沙箱。Shell 拥有 Shizuku 的 shell/root 能力，能修改系统、执行输入命令、读取其他获准范围和安装应用，其他开关不能限制这些系统命令。只在需要时开启，并使用自己管理或信任的中继。

权限防护在手机应用执行，必须安装 Android 64 才生效；旧手机只升级 Mac 或中继不会得到手机端限制。通过旧版远程安装 Android 64 后，新权限默认关闭，可能暂时无法从远程查询安装输出；在手机上开启所需权限，或通过已授权本地 adb 核实。Mac 26 和中继 4 的请求收紧另需分别更新，三端构建、安装和恢复独立验收，见 [发布记录](releases.md)。

本仓的本机回归使用模拟客户端和临时中继，不读取真实令牌或连接生产主机。手机开关、进程生命周期、真实网络以及生产配置和权限须在对应设备、部署授权内另行验收；源码审计不代表生产环境已经安全。
