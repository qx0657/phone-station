# 共享剪贴板

日常操作见 [README](../README.md#共享剪贴板)。入口是 Mac 与手机首页的「共享剪贴板」。首次安装共享与自动同步默认开启；开启共享时同时开启自动同步。「同步 Mac 图片到相册」是独立开关，默认关闭，手机保存设置，两端共用。升级保留已经关闭的共享设置；旧版或 MCP 单独暂停过自动同步时，页面提供「恢复自动同步」。两端页面不显示剪贴板正文或手动复制按钮。未保存过 MCP 开关时，服务默认跟随共享设置启动；明确关闭过 MCP 的仍保留该选择。

## 后台读取

Android 10 起普通后台应用不能读取剪贴板，仅前台有焦点的应用或默认输入法可以读取。因此手机工位使用已经授权的 Shizuku 13+ 创建专用 `ClipboardUserService`，以 shell/root 身份调用系统剪贴板服务；它只提供读取、写文字、停止三个操作，不执行 shell 命令，不改变输入法，不抢焦点。

服务核实 Binder 调用方必须是手机工位 UID，并在系统调用前清除传入 Binder 身份。系统调用使用 `com.android.shell` 的包身份及手机工位所在 Android 用户，默认设备编号为 0。系统接口签名按运行版本检测。PGT-AN20 的 MagicOS 9 在读取接口末尾增加 `userOperate` 布尔参数；适配已知接口并传 true，未知签名拒绝调用。关闭共享、停止 MCP 或 Shizuku 不再可用时释放服务，清除预览。APK 更新后重新绑定独立版本的服务。

手机锁定时返回 `locked`，不读文字也不自动写入。`ClipDescription` 的 `android.content.extra.IS_SENSITIVE` 为 true 时不传文字；Mac 遇到 `org.nspasteboard.ConcealedType` 或 `org.nspasteboard.TransientType` 同样跳过。本 App 复制 MCP 授权头时附加 ConcealedType。敏感标记由复制内容的应用提供，未标记的文字不能据此识别。

## 交换与冲突

Mac App 在运行期间每约 0.8 秒采样当前 Mac 剪贴板，并通过统一网关调用 `station_clipboard_exchange`，一次只允许一个交换请求；请求等待期间仍采样最新复制，正文不显示在界面。Mac 16 起，远程空闲交换在上次请求完成后至少等待 2 秒，新 Mac 复制与打开共享页可跳过这段等待；本地轮询频率保留。共享关闭时调用只读设置，不读取系统剪贴板；共享开启时交换 Mac 当前文本和手机当前文本。手机页仅显示既有会话状态，打开页面不额外读取系统剪贴板，也不提交交换。首页使用无正文、无需后台绑定的类型元数据区分锁屏和跳过状态。手机权限和服务均可用、最后收到成功的 Mac 交换超过 10 秒时，详情显示「手机端已就绪，待 Mac 接入」，首页功能行以次要色显示「待 Mac 接入」，不把这个心跳当作电脑通道断开，也不列为首页告警。图片或文件被跳过不改变会话就绪状态，也不显示暂停；敏感文字仍显示「已跳过」。文字没有历史记录，不写入偏好、文件或日志；偏好只保存共享、自动与图片设置。MCP 仍支持显式 `automatic: false`；仅传 `shared: true` 时自动开启同步。

使用手机随机版本、Mac `NSPasteboard.changeCount` 以及本次运行的客户端 UUID。手机读取内容与 `ClipDescription.getTimestamp()` 的复制事件标记，相同文字重新复制也会产生新版本；不比较两端时钟。首次接入、长时间断线或服务重启，只建立基线，不覆盖已有内容。自动同步开关改变也会重建基线。之后 Mac 发生复制且手机仍是上次观察版本时，把 Mac 文字写到手机；手机版本改变时，把手机文字写到 Mac。手机写入前再读一次、写入后核对结果。两端同时变化时手机版本优先；Mac 在请求途中又复制时，旧响应不得覆盖那次新复制。

回传内容相同时不再次写入；相同 Mac 版本的重复请求不重复写。业务请求不进入网关跨通道重放白名单；短暂超时或断线后先用 `station_clipboard_state` 的 `refresh: true` 只读核对手机当前版本，不更新 Mac 的复制版本，也不重放结果未知的交换请求。距上次成功交换不到 30 秒、手机服务未重启、手机版本未变时，比最后一次已发送请求更新的 Mac 复制可以继续同步；等待请求期间连续复制只保留当前最新一份。手机在切换期间复制、Mac 没有新复制时，也可恢复手机到 Mac 的同步。两端同时变化、超过恢复窗口或服务重启时重新建立基线。两条通道共用手机应用中的状态与服务，因此切换 adb/远程本身不会制造回传循环。

支持文字与链接，按 UTF-16 长度最多 100000；只取 Android 第一个 ClipData item 的文字，不读取手机图片或文件 URI。Mac 文件 URL 即使同时提供路径字符串或图片表示也跳过。目标端当前是敏感内容、图片、文件或超长文字时，同样不自动覆盖。剪贴板清空、图片、文件、超长文字和敏感内容只更新类型状态，不自动覆盖另一端。远程经现有 HTTPS 与证书公钥指纹校验的中继转发；中继能读取文字及开启后的图片，使用自己部署或信任的服务。

## Mac 图片保存到手机相册

图片同步默认关闭；关闭时只采样图片类型，不读取图片字节。开启后仅对新复制事件读取 PNG 或 TIFF，并统一编码为 PNG，通过已有交换请求的 `macImage` Base64 传输。单张上限 4 MiB、3200 万像素，文件 URL 和敏感标记优先跳过。首次连接、开关变化、长时间断线与重启只建立基线；图片结果未知时不自动重传。手机用 Mac 客户端与复制版本防止重复保存，保存前再次核对手机版本，锁屏或敏感内容时不保存。

手机通过 MediaStore 创建 `Pictures/手机工位/Mac-<随机标识>.png`，先用 `IS_PENDING` 隐藏未写完的项目，写完再发布并通知相册观察者，不使用旧的 file URI 扫描广播。保存失败清理未完成项目，返回 `imageError`，不把相册错误报成 Shizuku 权限故障；重新复制后可以再次尝试。图片字节不进入快照、日志或偏好，手机相册中的图片会保留，关闭同步不删除。此功能只将 Mac 图片保存到相册，不读取手机图片，也不向手机剪贴板写入图片 URI。

图片发布成功后，`ClipboardImageNotice` 在独立的 `clipboard-images` 通道显示「Mac 图片已保存到相册」，默认无声、无震动。固定 tag/id 只保留最新一条，点击通过不可变 PendingIntent 直接打开该图片的 MediaStore URI，并授予查看器临时读取权限；点击后通知自动收起。不显示缩略图或真实内容，锁屏按系统隐私设置处理。首次基线、重复请求、跳过与保存失败不发成功提示。通知权限或该通知类别被关闭时，存图仍成功；通知发布异常不删除已经存好的图片，也不重新保存。

Mac 首页与共享页显示剪贴板自身的状态：等待连接、正在核对、正在恢复同步、自动双向同步或锁屏暂停。通道已连接不代表剪贴板已就绪；请求等待超过 2 秒时显示正在核对，完成实际交换后再显示同步可用。诊断日志只记录中断和恢复事件，不记录剪贴板内容。Mac 最近同步时间仅在实际应用手机文字或手机确认已应用 Mac 文字时更新，建立基线和空闲心跳不更新；记录只保留在本次进程内。

## 首页的功能提示

Android 49 与 Mac 0.1.0 (9) 把连接通道与功能可用性分开显示。Shizuku 未安装、未启动、未授权及版本或身份不满足要求时，首页直接说明共享剪贴板和远程 shell 不可用，并提供权限处理入口；不再把这些状态排除在权限待处理项之外。读剪贴板的后台服务绑定失败单独显示原因，不能统一写成「请先授权」。

手机首页每秒检查可读取的权限与已开启功能，文件权限、系统设置写入、提醒显示、电池优化、精确闹钟、MCP、通知同步的授权/白名单/监听，以及配置过的远程通道故障统一收成一条「有 N 项需要处理」。点开「权限与检查」后查看影响与处理方法，已满足的权限默认折叠。正常的远程「连接中」、连接待确认和等待 Mac 剪贴板/通知会话不报手机设置故障；完整诊断仍在 `station_device_status` 的 `health.issues` 中，首页与检查页通过 `HealthStatus.attention` 筛出实际待处理项。同一个 Shizuku 问题不再附加一条「Mac 未连接」。未开启的剪贴板或通知同步不要求建立会话。自启动读不到，仍单独提供手动检查，不声称已经核实。

`station_device_status` 返回无正文的 `health.issues`，每项包含 `id`、`title`、`detail` 和 `destination`。Mac 后台本地每约 3 秒、远程在上次请求完成后至少 15 秒只读刷新，打开面板可立即刷新。从 0.1.0 (15) 起，首页只更新固定功能入口的单行摘要，权限诊断与处理入口放在「更多工具与设置 → 手机权限与状态」；Mac 通知显示权限与接收状态仍在「手机通知」入口和详情页。剪贴板核对、连接等待和权限变化不再在首页顶部增删提示卡，避免改变弹窗高度和按钮位置。断开后清除旧诊断，请求失败显示尚未核对。权限诊断不启动 Shizuku、不弹授权框，不读取剪贴板、不消费通知，也不提交同步交换。Android 首页不等待剪贴板 UserService 绑定，后台连接故障不阻塞主界面。

## Mac 16 的请求调度与慢响应

原设计在交换请求等待 2 秒后直接清除 `connected`，把远程排队与网络延迟写成「正在核对剪贴板」。网关远程确认超过 6 秒且仍忙碌时，Mac 还会清空访问地址，使剪贴板和通知误判为断线。另一个放大排队的原因是每次网关状态或 RTT 更新都会触发远程控制检查，即使面板已经收起。

16 版把 App MCP 请求放进同一个可取消队列：用户操作优先于后台诊断，连续三次越过旧请求后让最早请求先执行，避免诊断饥饿。HTTP 超时与剪贴板慢响应计时从实际发出开始，不包含 App 排队时间；文字请求超过 6 秒、图片请求超过 25 秒才显示「同步响应较慢」，不据此清除连接。实际失败或通道不可用才进入恢复，仍先只读核对，不重放未知结果。远程已知在线但忙碌、确认过期时保留可发送的地址与令牌；菜单栏仍显示确认中，不把未确认的连接报成已连接。真正离线、配置变化或空闲确认过期仍停用通道。

远程通知后台轮询在上一轮完成后至少等待 2 秒，显式刷新立即执行。远程控制只在面板显示期间定时核实，上一轮结束后至少等待 10 秒；打开面板和用户操作后仍立即核实，能力快照最长保留 30 秒且必须属于同一通道。普通 RTT 更新不再额外发起控制检查。网关排队支持上下文取消，客户端已经超时的请求不会在轮到它时再发给手机。日志只记录工具名、排队/请求耗时、错误码及每 30 秒的完成/失败数，不记录令牌、剪贴板或通知正文。

完整构建、Go race 与原有恢复/冲突/图片去重回归通过。新增 `ClipboardTransportTest` 使用本机独立 HTTP fixture，让一个诊断请求占用 9 秒，确认剪贴板等待超过原来的 8 秒预算后仍未误报断线，轮到发送后成功同步模拟的新文字。fixture 使用随机本地端口和内存剪贴板，不接入手机、不修改真实剪贴板。队列取消、用户操作优先、远程空闲轮询间隔、忙碌通道保留和空闲过期拒绝也有回归覆盖。

剪贴板状态增加 `availability`，包含 `status`、`reason`、`action`、`ready`、共享设置和会话状态。手机与 Mac 共享页使用具体的依赖状态。Mac 的权限处理入口通过已导出的 `MainActivity` 跳转到应用内部权限页；权限页和剪贴板页继续不对外导出。没有 adb 时说明从手机首页进入权限，不尝试经尚不可用的 Shizuku 打开自身权限。

## 工具

| 工具 | 参数与用途 |
| --- | --- |
| `station_clipboard_get` | 只读手机当前剪贴板，返回 `kind` 和非敏感的 `text`，不依赖共享开关 |
| `station_clipboard_state` | 只读共享、自动开关、已有预览、手机版本和 Mac 在线状态；可选 `refresh: true` 只读刷新手机当前内容，不消费 Mac 版本 |
| `station_clipboard_configure` | 可选 `shared`、`automatic`、`images` 布尔值，改变设置；`images` 默认 false |
| `station_clipboard_exchange` | Mac 提供 `clientId`、`macVersion`、`macKind`、可选 `macText` / PNG Base64 `macImage`、上次 `phoneVersion`；省略客户端参数只刷新手机预览；可选 `resume: true` 在只读核对后恢复短暂切换期间的新文字复制；可能写手机剪贴板或保存图片到相册 |
| `station_clipboard_set` | 原来的手动写手机文字工具；应用自身写入，不要求共享开启或 Shizuku |

共享关闭时状态的两端预览为 null。共享开启但 Shizuku 不可用时返回明确的 `error`；Mac 不用错误响应执行任何自动写入，手机页提供权限入口。`station_clipboard_get` 的 `kind` 与交换结果的 `phone.kind` 可以是 text、empty、unsupported、sensitive、oversize、locked；`mac.kind` 另支持 image，仅返回类型，不返回字节。状态返回 `images` 与 `imagesSupported`，成功存图返回 `savedImage: true`；Mac 对旧手机继续发送 unsupported，不传图片。
