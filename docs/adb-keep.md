# android.sh

## 同一手机的 mDNS 别名

2026-10-02，PGT-AN20 在 `adb devices -l` 中同时出现常规 mDNS 序列号和带空格、`(3)` 后缀的别名；断开重复项后，adb 的 mDNS 自动连接仍可能再次建立别名。解析设备列表必须把 `device` 状态之前的整段保留为序列号。`lib/adb_mdns.py` 遇到多条在线连接时读取 `ro.serialno`，同一物理手机合并后选择不带空格的 mDNS 名称；不能仅按型号归并，否则两台同型号手机会被误当一台。`online_serial` 和 MCP 配对、状态刷新共用这套规则。配对的两枚令牌通过标准输入读取，连接发现过程的 adb 子进程将 stdin 接到 `/dev/null`，避免提前吃掉令牌输入。

## 应用和安装

无线调试保持是手机上「手机工位」里的一项功能。Wi-Fi 连着、USB 调试还开着时，它把被系统关掉的无线调试重新打开。桌面和通知上的名字是「手机工位」。`android.sh` 优先远程更新并保留现有权限；首次安装或需要补权限时用 `android.sh --adb`，授好这项功能要的写入权限。会话提醒的下拉通知也由这个应用发出，见 [notify.md](notify.md)。安装入口还放在这个脚本上。以后手机上要在 adb 断开之后还做的事，也放进同一个应用。日常用法见 [../README.md](../README.md) 的「Android 应用」。

包名是 `dev.phonestation.adbkeep`，是这项功能先单独做出来时留下的。换包名会卸掉重装，写入权限和荣耀的启动管理都要再来一次，所以先留着。源码在 `lib/android/`，没有 Gradle，也没有 AndroidX。

## 开关为什么会自己关

无线调试的开关是 `settings global adb_wifi_enabled`。USB 调试是 `adb_enabled`。

AOSP 的 `AdbDebuggingManager` 在 Wi-Fi 关闭，或当前 Wi-Fi 网络断开时，把 `adb_wifi_enabled` 写成 0。Wi-Fi 重新连上不会写回 1。荣耀的省电说明里，闲置和离开开发者选项也会关。这台上没有把这几种触发拆开实测；用户碰到的是断开之后开关自己关掉，下次要进开发者选项再开一次。

USB 调试还开着时，`adbd` 不会停，但这条 TLS 会话已经断了。电脑上没有 USB 时，看不到手机，也写不了这个设置。

下面几项解决的是别的问题，留着原值：

- `allow_charging_adb` 是荣耀「仅充电模式下允许 ADB 调试」。这台上已经是 1，无线调试仍会关。
- `adb_allowed_connection_time=0` 是 AOSP 里「一直允许」的授权窗口。它管的是已配对电脑要不要重新点允许，不管总开关。
- 已保存的 Wi-Fi（trusted BSSID）只是跳过「允许这台设备无线调试」对话框，不负责把开关保持为开。
- 这台 MagicOS 9 的设置里没有 AOSP 那个无线调试快捷开关。`com.android.settings` 里能查到的快捷开关只有助听器。

`persist.adb.tls_server.enable` 和 `service.adb.tls.port` 在这台 PGT-AN20 上，无线调试开着时用 shell 读仍是空的。不要拿这两个属性判断开关。

## 为什么不是电脑上的常驻，也不是 Shizuku

电脑上的进程只有在 adb 还在线时才能写设置。开关已经关掉、又没有 USB 时，它无事可做。

手机上的 Shizuku（`moe.shizuku.privileged.api`）和 Brevent（`me.piebridge.brevent`）装过。Shizuku 的启动器 fork 之后 `setsid`，服务进程脱离拉起它的那条 shell。设计上一直运行到重启，启动之后可以关掉无线调试。这台手机没有 root（`ro.boot.flash.locked=1`，`ro.build.tags=release-keys`）。2026-10-01 看进程时没有 `shizuku_server`，只有普通应用进程。没有把无线调试关掉再看它还在不在。重启之后它自己起不来，要无线调试已经开着才能再启动。

所以盯开关的是手机上的「手机工位」，无线调试保持是它里面的一项。进程不挂在 adb 会话上，`WRITE_SECURE_SETTINGS` 由 adb 授一次，之后自己写 `adb_wifi_enabled`。

手机工位另外也是 Shizuku 的客户端。清单里有 `moe.shizuku.manager.permission.API_V23`，provider 是 `rikka.shizuku.ShizukuProvider`，authority 是 `dev.phonestation.adbkeep.shizuku`。服务在跑时，权限页可以向它申请授权。授权留在 Shizuku 里。构建从 Maven 取 API 13.1.5，放到 `build/third_party/shizuku/`，不入库。`station_shell_exec` 通过 Shizuku 13+ 的 UserService 执行命令，本地和远程 MCP 共用；`station_shell_status` 读取可用状态。文件、亮屏和通知仍走应用自己的权限，不经过 Shizuku。启动、权限和执行边界见 [mcp.md](mcp.md#shizuku-shell)。

## 它什么时候写

三个条件同时成立才写 1：应用里的「保持无线调试」开着（默认开）、`adb_enabled` 是 1、当前有 Wi-Fi 网络。USB 调试被关掉时不写，避免把用户关掉的调试重新打开。

Wi-Fi 用 `ConnectivityManager.getAllNetworks()`，认 `TRANSPORT_WIFI`，不要求它是默认网络，也不要求 `NET_CAPABILITY_INTERNET`。这台手机开着 Clash 时，默认网络是 VPN；按默认网络判断会以为没连 Wi-Fi。`getAllNetworks()` 已过时，这里仍用它，就是为了在 VPN 下面看见 Wi-Fi。

系统若觉得当前网络不可信，会把刚写上的 1 立刻拨回 0，并弹出允许对话框。写入之前先把失败次数加一，所以观察者被这次拨回唤醒时，不会马上再写。等待依次是 0、3 秒、15 秒、1 分钟、5 分钟。开关保持为开超过 1.5 秒，或 Wi-Fi 网络的 handle 变了，失败次数清零。平时每 15 分钟再看一次。这段判断在 `KeeperPolicy`，构建时在电脑上跑。

前台服务类型是 `specialUse`。精确闹钟作兜底；`setExactAndAllowWhileIdle` 被拒绝时退到 `setAndAllowWhileIdle`。开机广播和「自己被更新」广播也会拉一次。服务没有 exported：这台 Android 15 上，shell 执行 `am start-foreground-service` 会报 `Requires permission not exported`。安装脚本只启动界面，由应用自己的进程拉起服务。

## 界面

首页为连接概览和 MCP 服务、共享剪贴板、通知三个核心入口，上方是应用标题和「设置」入口。原生字体、浅色／深色主题和语义状态色保持一致。连接概览内的「暂停／恢复使用」控制总开关，保存期间禁用按钮并显示进度；功能选择、配对和资料都会保留，系统无线调试不随暂停关闭。

连接概览显示电脑是否实际连通，以及无线、USB、远程等实际连接方式。连接设置按「本地连接」「远程连接」分组，不重复首页的大连接状态卡片。本地组包含无线调试、自动保持与只读 USB 调试状态，远程组提供状态与配置入口。底部「连接检查」默认收起，展开可查看 Wi-Fi 网络、本地电脑实际连接、本地 MCP、远程通道和调试写入权限；这些检查只读取状态，并提供 MCP 服务与权限检查入口。连接恢复与手动切换的具体问题仍直接显示在相关设置下方。

手动操作由 `WirelessControl` 定义规则，`KeeperEngine.setWireless()` 与自动恢复的 `tick()` 使用同一把锁。手动关闭先同步保存自动保持为关，再写 `adb_wifi_enabled=0`，避免设置观察者重新打开；保存失败不改系统开关，系统写入失败恢复原来的保持选择。手动打开只写无线调试，不打开 USB 调试，也不改变保持选择；写入前记录尝试时间，避免系统因网络未获允许拨回后立即重试。界面始终读取系统实际值，切换后约 1.5 秒再次核对，失败给出说明，不自动重做手动操作。没有写入权限时显示处理说明，手动切换不会写入；开启自动保持会引导查看权限。开关和导航文字允许两行，触控区域至少 48dp。

首页「MCP 服务」进入独立服务页：紧凑状态区合并本地与远程的可用性，能力按文件访问、命令与安装、屏幕与手机控制分组；点击只显示该组的功能与权限。接入方式包含本地 MCP 开关、远程连接和本地连接设置入口，地址与说明默认折叠。已有远程配置默认收起，展开后可修改地址、指纹和手机令牌；令牌不回填。详情见 [mcp.md](mcp.md)。

设置页包含功能管理、权限与检查、远程访问范围、连接设置和关于，使用原生返回与滚动，不再需要侧栏或边缘手势。旧侧栏交互验证见 [界面历史](history/adb-keep.md)。功能管理保留全部子开关，正常状态不再重复显示开启／关闭说明；缺少权限时提供具体原因与直接处理入口。

首页的真实权限或服务问题合并为一条可点击提示；剪贴板与通知等待 Mac 会话时，仅在各自功能行显示状态。关于仍显示安装版本和作者。接入信息与说明位于 MCP 服务页的折叠区域中，本机地址明确标为手机本机使用。

通知页、权限页、铃声页、MCP 服务和关于用同一套返回和卡片。通知页分别控制「手机通知 → Mac」与「电脑提醒 → 手机」，后者提供显示方式、提醒弹出及铃声。正常状态的权限与规则折叠在「使用说明与权限」，缺少权限或服务时直接显示处理入口。铃声默认「跟随系统」，用的是系统通知铃声。点「铃声」打开本应用的列表：第一项跟随系统，第二项静音，后面是系统通知铃声。当前选中的那一项是绿的，右边有一枚勾。点一项就选定，并试听；静音不播。静音仍发通知。这台 PGT-AN20 的系统铃声页里没有跟随系统和静音，所以这两项放在应用自己的列表里。电脑上 `notify.sh --sound` 指定的那一次仍用指定文件，不看这里。

「提醒弹出」默认开。开着时，会话提醒在屏幕上弹出；关掉就只进下拉栏。常驻的「手机工位」那条不走这个开关，仍是低重要程度。系统建好通知通道后不允许应用再改重要程度，所以弹出和不弹出是两条通道，见 [notify.md](notify.md)。

「权限与检查」页优先列出待处理的权限与功能问题，每项说明影响和下一步，能处理的项可进入对应设置；已满足的权限默认折叠，点「已满足的权限」展开或收起。页面每秒只读检查，结果变化才更新列表，展开状态在主题与字号变化时保留。写入系统设置需要在电脑上运行 `./scripts/android.sh --adb` 补权限，权限行本身不能申请。Shizuku 没安装写「未安装」；服务没在跑写「未启动」，点一下打开 Shizuku；服务在跑但还没允许写「未授权」，点一下弹出 Shizuku 的允许。Shizuku 用于 shell 工具和剪贴板后台读取，不可用时计入待处理数量，同一个原因只显示一次。已授权仍写「已授权」。重启后服务要在 Shizuku 里再启动，授权还在。自启动读不到，放在独立的「后台运行」分组，固定写「去设置」，不计入待处理数量。正常等待 Mac 会话也不计入检查问题，完整会话诊断仍保留在 MCP 状态里。文案在 `PermissionCopy`，和打开时机一起在电脑上跑。

下拉栏一条常驻通知，渠道 id 是 `keep`，显示名是「手机工位」。重要性低，无声，无角标，不显示时间。点通知打开应用。点「清除」清不掉。

常驻通知以电脑连接为主状态。收起时显示标题和一行简短补充，有问题时补充优先显示问题，已选择远程通道的确认状态也不会被本地在线掩盖。展开后分为两行：第一行分别显示本地与远程连接，第二行显示 MCP 实际状态和自动保持选择。名称与状态上下对齐；连接用 Wi-Fi／USB／电脑和云图标，自动保持用循环箭头，不再以成功勾选图标表达偏好。辅助功能名称使用完整名称和实际状态。布局保留系统的应用标识、展开按钮和点击主体打开首页的行为，通过 `DecoratedCustomViewStyle` 承载，见 [Android 自定义通知](https://developer.android.com/develop/ui/views/notifications/custom-notification)。不要在通知布局里放普通的 `View` 当间隔：这台 Android 15 的通知胀不开 `android.view.View`，前台服务会被系统杀掉，打开应用就闪退。图标使用已着色的位图交给 `RemoteViews`。

adb 或远程任一实际在线时，标题为正文色「电脑已连接」；本地按真实通道显示「无线」「USB」或「本地」，不把无线调试开关当成连接。未使用远程不报故障，已选择远程的待配置、连接中、待确认或失败状态独立显示。MCP 和首页共用服务汇总，区分运行中、部分可用、连接中、需设置、未开启与暂停，服务实例存在不能代替监听或远程连通事实。没有在线连接，但无线调试已开启、MCP 可用或正在建立远程接入时，标题为「等待电脑连接」；远程待确认时为「确认电脑连接中」，都不可用时为「电脑未连接」。总开关暂停优先于旧在线状态。Wi-Fi、调试开关、心跳、远程与自动保持状态变化都会更新同一条通知，远程线程先切回主线程，即使保持服务关着也会刷新；MCP 完成启动后立即刷新真实监听状态。

自动保持显示「已开启／已关闭」选择，开启时仍使用中性色；恢复问题单列在底部，例如「自动保持等待 Wi-Fi」或「自动保持缺少写入权限」。它和 MCP 问题均使用提示色，并保留已经在线的 USB 或远程连接标题；主动关闭自动保持后隐藏它的恢复提示。需要手动处理时提供原生「MCP 设置」「权限设置」「连接设置」或「Wi-Fi 设置」按钮；等待自动恢复和退避没有额外按钮，不显示倒计时。文案在 `StationNote`，和 `KeeperCopy` 一起在电脑上跑。两项服务的 `onConfigurationChanged` 会刷新通知；去重键包含夜间模式、字体缩放和密度，文字状态没变也会重新着色，不因主题变化把已划掉的通知叫回。超过 1.3 倍字号时收起区使用系统模板分配标题和正文；展开文字可换行，本次尚未完成新版真机外观与点击验收，见 [68 版记录](history/adb-keep.md#68-版常驻通知分层)。

「保持无线调试」关着、MCP服务也关着时，没有这条通知。只开着其中一项时通知还在，关着的那项写成关着。两项共用这一条，不再为 MCP 另起一条。

划掉之后服务还在。这台上往旁边划会先露出「删除」，点掉之后它才从下拉栏消失，大约半秒后换一个 id 自己再出现，不响。划掉之后同一个 id 再交给前台服务，不会回到下拉栏，所以每次再出现都换 id。id 从 1 起，避开会话提醒的 2 和 3，也不再用合并前 MCP 那条的 4，到 500 再从 1 绕回去。十五秒里连续划掉超过八次，就先停住，不再自动回来；打开「手机工位」，或无线调试、MCP、连接这三项里有一项变了，会再发出来。

「MCP 服务」中的「本地 MCP 接入」只控制本地监听；关闭时已开启的远程客户端继续运行。启用或保存远程连接不改变本地选择。Mac「停止手机 MCP 服务」与 `mcp.sh stop` 会同时关闭两项；首页「暂停」则保留各项选择，以便恢复。服务摘要考虑本地与远程，支持仅远程运行；整体暂停覆盖延迟的在线状态。接入故障与正在连接区分，本地开启但没有监听时提供重启入口，不自动重试用户操作。本机地址只在本地服务实际运行时显示。地址和通知的说法见 [mcp.md](mcp.md)。

首页连接概览随实际连接刷新；连接设置不重复显示这块概览。

打开应用时，若「保持无线调试」还开着，界面会让保持服务再看一眼。通知还在下拉栏里就不动。已经划掉、又还没自己回来时，这一眼会把它再发出来。

横向一行里，右侧的开关和状态值必须是自身宽度。写成占满父级宽度时，左侧名称宽度变成 0，屏幕上只剩右边的开关和状态。

## 和电脑的连接

顶部合并 adb 心跳与远程通道：任一在线就显示「已连接」。adb 心跳仍看 `settings global phonestation_host_ms`，值是手机本地时间的毫秒；`phonestation_host_transport` 由电脑按 adb 序列号写成 `wireless` 或 `usb`，供副标题显示连接类型。心跳过期后不再显示该类型；无线连接还要求 Wi-Fi 连着、无线调试开着，任一不满足就立即失效，不等心跳过期。USB 心跳不受 Wi-Fi 开关影响。电脑连着时大约每 2 秒写一次，不超过 6 秒算在线，0 或空不算。时间用手机上的 `date`，不用电脑的时钟。远程开关开启且当前 `PhoneRelayClient` 在最近 6 秒收到中继成功应答，也算在线；使用单调时钟计时，只有配对或开关打开不算。长操作超过确认窗口时显示「确认连接中」，收到结果提交或轮询应答后恢复；连接失败与认证失败分别显示原因，保持自动重试。关闭或轮询失败会清掉远程连接状态，旧客户端退出不会覆盖新客户端的状态。

写入由 `scripts/host-state.sh` 做。`connect.sh` 连上之后在后台跑 `host-state.sh watch`，直到没有在线设备。已经有一个在写就不会再开一个。菜单栏 App 下次构建之后，设备检查看到在线设备时也会跑一次 `host-state.sh mark`。`disconnect.sh` 在这次断开之后不会再留下设备时，先停掉写入，再把这个值写成 0。还留着 USB 时不写 0，写入继续。

断开之后电脑进不去手机，所以不能靠断线之后再写一次来复位。复位有两条：主动断开时，断开前还能写的那一下写成 0。会话自己断掉、来不及写 0 时，旧时间过了 6 秒就不再算 adb 在线；Wi-Fi 断开或无线调试关闭会立即使无线心跳失效。配置里可以留着那个旧数字。远程仍在线时界面继续显示已连接，两条通道都不在线才变成未连接。

不看系统那条「已连接到无线调试」。2026-10-01 这台上，无线会话还在时，用户把这条通知划掉了，活动通知里就没有包名 `android`、id 62。通知没了，不代表电脑没连着。全部清除也会把它清掉。开关 `adb_wifi_enabled` 只说明在听。`dumpsys adb` 里的 `connected_to_adb` 只表示调试线程在跑。`service.adb.tls.port` 在这台上无线调试开着时仍是空的。应用也读不了 `/proc/net/tcp` 和 `/proc/net/tcp6`。不要用这些判断顶部的连接状态。

## 权限和启动管理

`./scripts/android.sh --adb` 的本地安装流程会 `pm grant` 这两项；远程更新保留已有权限，不重新授予：

- `WRITE_SECURE_SETTINGS`：写 `adb_wifi_enabled`。普通应用不能在界面里申请，只能由 adb 授。
- `POST_NOTIFICATIONS`：常驻通知。渠道 `keep`，重要性低，无声，同一条不重复响。

同时用 `appops set --uid` 授 `MANAGE_EXTERNAL_STORAGE`（所有文件访问）。`pm grant` 授不上这项。MCP服务怎么开、能碰到哪些路径，见 [mcp.md](mcp.md)。

同时把包名放进 `deviceidle` 白名单。这就是忽略电池优化。权限页上「电池优化」读 `PowerManager.isIgnoringBatteryOptimizations`。没放开时，点那一行会问要不要设为不受限制。清单里的 `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 只为了能打开这个询问。

精确闹钟用清单里的 `USE_EXACT_ALARM`。权限页读 `canScheduleExactAlarms`。没允许时，点那一行打开「闹钟和提醒」。

通知权限安装时已经 `pm grant`。这还不够让会话提醒在屏幕上弹出。这台 MagicOS 会把新建的「提醒」通道从高降到默认，要在该通道里勾上「横幅通知」才锁回去。通道没有声音时，勾选也不会抬上去。`android.sh` 会在重启应用后去勾；已经是高就不点。屏幕锁着或这一页没打开时，脚本说明要到权限页点「通知」再勾。权限页同时看通知权限和这条通道是不是还能弹出。应用里把「提醒弹出」关掉时，不把「不弹出」算成缺权限。细节在 [notify.md](notify.md)。

荣耀的应用启动管理拦自启动。shell 里没能替用户打开这项，应用也读不到开没开。重启后要自己起来，需要在应用启动管理里允许自启动和后台活动。权限页点「自启动」先判断 `Build.BRAND` 或 `Build.MANUFACTURER` 是否为 HONOR（不区分大小写）。仅荣耀手机尝试 `com.hihonor.systemmanager` 的专用入口，优先打开 `startupmgr.ui.StartupNormalAppListActivity`，这是 PGT-AN20 Android 15 上普通应用可用的「应用启动管理」入口。其他品牌直接走 Android 默认应用详情页（`ACTION_APPLICATION_DETAILS_SETTINGS`，带本应用的 `package:` URI）；荣耀的专用入口全部不可用时也回退到此页。应用详情页不可用再尝试系统应用设置列表，仍失败则提示手动查找后台运行或自启动设置。系统设置自己使用的 `appcontrol.activity.StartupAppControlActivity` 要求 `com.hihonor.systemmanager.permission.START_MODULE_UI`，保护级别为 `signature|privileged|preinstalled`，普通应用声明也不能获得；旧代码没有捕获 `SecurityException`，点击后崩溃，看起来像重启应用。53 版改为普通入口优先，并同时处理页面不存在和权限拒绝；保留 AppControl 作为荣耀手机的兼容候选。55 版增加品牌判断和系统默认设置回退。在系统里强行停止之后，进程不会自己回来，需要再打开一次应用。开机这条路径没有在这台上重启验证过。

## 构建

`lib/android/build.sh` 用本机的 OpenJDK、Go 1.23+、`platforms/android-35` 和 build-tools 打包。Go 将独立的 PTY 辅助程序交叉编译为 Android/arm64 可执行文件并放入 APK assets，无需 NDK；由已授权的 Shizuku 以 shell/root 身份运行，应用 UID 不执行它。没有这些时，先按 [android-cli.md](android-cli.md) 安装 SDK，再执行 `android sdk install platforms/android-35 build-tools/35.0.0`。

签名存在 `~/.phonestation/adb-keep.keystore`。要换目录就设 `PHONE_STATION_KEY_DIR`，文件名仍是 `adb-keep.keystore`。这份不入库。原来的 `build/adb-keep.keystore` 若还在、而新位置没有，构建会把它拷过去，不删旧文件。删掉 `build/` 不会换签名。密钥目录固定为 0700，密钥与 `adb-keep.password` 固定为 0600；密码经文件传给 keytool/apksigner，不进入进程参数。新密钥使用随机密码。旧的公开 `android` 密码会重新加密为随机密码，转换前后比较签名证书，保留原签名身份；中断后可恢复，已有无效或未知密码的密钥不会被替换。也可用 `PHONE_STATION_KEY_PASS_FILE` 指定已有私密密码文件。换电脑时安全备份并一起恢复密钥和密码文件，不能只拷密钥。安装脚本遇到 `INSTALL_FAILED_UPDATE_INCOMPATIBLE` 会停止并保留原应用和数据，需要相同签名的安装包，不再自动卸载。

公开的 `android.jar` 里没有 `Theme.DeviceDefault.DayNight.NoActionBar`。主题父级用 `Theme.DeviceDefault.DayNight`，再关掉标题栏，于是跟着系统的深色和浅色。这个主题从 Android 10 才有，所以最低系统是 29。这台手机是 Android 15。图标是包里的自适应图标：蓝底、线框手机、手机里一条短横。通知小图标是同一支手机，中间空出这条短横。

菜单栏「更多工具与设置」里的「安装或更新手机应用」跑的就是这个脚本。仓库里运行时它先编 APK。打进菜单栏 App 的那一份旁边没有源码，装的是构建时放进去的 `phone-app.apk`。无线调试保持仍在手机上的「手机工位」里。

`android.sh` 已支持远程优先更新：中继与 Shizuku 可用时，不连接 adb，通过 `install-apk.sh` 上传、校验并安装；只有上传前检查远程不可用时，默认模式才走本地 adb。`--remote` 只走远程，`--adb` 只走本地。远程更新保留配对和现有权限，等待应用自身替换后重新上线；原有 adb 模式仍负责首次安装及权限设置。安装结果未知时查询原任务，不再次安装，见 [remote-ops.md](remote-ops.md)。
