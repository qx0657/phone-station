# 功能开关与权限

手机首页连接概览内的「暂停／恢复使用」是总开关。「设置 → 功能管理」集中管理通知、剪贴板、文件、命令、画面与控件。Mac「设置 → 手机功能管理」查看手机选择并提供手机页面入口。

首页「MCP 服务」把核心能力归为文件访问、命令与安装、屏幕与手机控制。每个入口只显示对应子开关和所需权限，完整列表仍在「设置 → 功能管理」。服务是否运行与功能选择、权限是否就绪分别展示；页面重组不改变已有开关和远程授权。

## 三层状态

| 控制项 | 表达什么 | 在哪里设置 |
| --- | --- | --- |
| 总开关与功能子开关 | 用户是否要运行手机工位及某项功能 | 手机首页与设置中的功能管理页 |
| 系统权限 | 已开启功能是否具备运行条件 | 开启时检查，缺项引导至对应系统设置 |
| 远程访问范围 | 已配对远程电脑可以调用哪些已开启功能 | 手机权限与检查 → 远程访问范围 |

系统授权不会自动开启功能，缺少权限也不会把功能开关拨回关闭。页面保留已开启的选择，同时显示具体缺项。单项检查除系统权限外也计入通知应用选择、接入服务和该功能需要的远程访问范围；直接进入对应处理页，不把「系统权限已满足」当成全部设置完成。保存中的状态和失败信息紧邻被操作项，暂停期间修改选择会说明恢复后生效。开启子开关时检查对应权限，重新开启总开关时汇总检查已有选择。关闭的功能不计为权限故障。手机通知 → Mac 与电脑提醒 → 手机各有独立子开关；Mac「在这台 Mac 接收」是该电脑的接收偏好，未授权通知时也可保存选择，真正接收仍需权限满足。

## 总开关

关闭后停止手机工位的 MCP / 中继客户端、无线调试自动保持、通知正文采集和剪贴板同步，结束应用持有的投屏、终端和手电筒服务。保持亮屏只恢复本应用保存的设置快照。后台任务和已经交给系统执行的安装、命令或文件操作可能已生效，不能通过关开开关重放，恢复后仍按原编号查询。

子开关、通知应用选择、中继配对、本地接入与自动保持偏好均保留。再次开启时按原偏好恢复服务，同步建立新基线，不补发旧通知或旧剪贴板内容。无线调试的系统开关保留原值，不通过关闭系统 adb 来切断用户的恢复途径。手机重启后的 Shizuku 仍需用户重新启动。

## 子开关与依赖

| 功能 | 主要系统依赖 |
| --- | --- |
| 共享剪贴板 | 已运行并授权的 Shizuku；锁屏和敏感内容继续跳过 |
| 手机通知 → Mac | 系统通知使用权、在手机选择应用；Mac 接收开关及通知显示权限 |
| 电脑提醒 → 手机 | 手机通知显示权限；横幅和铃声是显示方式设置 |
| 文件读取、修改、在手机打开文件 | 所有文件访问；永久删除仍需明确操作要求 |
| 截取画面 | Shizuku、所有文件访问；远程下载还需允许文件读取 |
| 投屏、录屏与操控 | Shizuku；远程画面还需已配置的中继和对应远程访问范围 |
| 电脑控制保持亮屏 | 写入系统设置；不以该开关代替实际亮屏状态 |
| 电脑控制手电筒 | 远程需 Shizuku；灯光跟随声音需本地 adb 和 Mac 音频权限 |
| Shell 与 APK 安装 | Shizuku；远程安装还需文件读取和修改开关及远程访问范围 |

升级会保留已有剪贴板、通知与远程访问选择，为原先没有独立开关的能力迁移原有可用行为。新安装的这些能力默认关闭，用户按需开启；开关迁移只执行一次。中继资料变更仍会清除远程访问授权，不扩大原来的安全边界。

## 执行边界

功能检查在手机工具执行层生效，工具列表同样过滤；批量调用、文件锁之后和特权服务绑定后再次检查。关闭功能会使旧连接请求失效，重新开启后旧请求不能借新选择继续启动。总开关只能由手机界面修改，MCP 与配对广播不能开启它。

随包本地 adb 投屏、录屏、截屏、提醒、亮屏和手电筒入口读取手机投射的功能状态。投屏 / 录屏运行期间定期检查，关闭后使用正常停止信号收尾录像；手电筒持有进程也检查开关。Mac 本地按钮读取相同状态。旧手机没有状态字段时保持兼容。

表中的 Shizuku 条件用于手机 MCP 与远程执行；本地 adb 的投屏、命令等继续使用已取得的系统授权，也受随包入口的功能开关检查。

这些是手机工位的应用控制，不能撤销电脑已获准的系统 adb 或 Shizuku shell 权限；外部直接运行 adb / shell 仍具有系统原有能力。Mac、MCP 和中继不能替用户开启系统通知使用权或选择通知应用。系统权限与 [远程安全边界](security.md) 继续同时执行。
