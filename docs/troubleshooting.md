# 故障排查

先看状态，再处理对应原因。查询结果未知的任务时使用原编号；不要把断线、超时或 `missing` 当作肯定没执行。

```sh
./scripts/mcp.sh status --safe
./scripts/mcp.sh profile
./scripts/status.sh
```

`status --safe` 只读已有网关且不输出令牌；其中的 `usage` 只有计数和时间，没有令牌或剪贴板内容。`profile` 显示地址、指纹与配置是否存在，不访问钥匙串。`status.sh` 查看本地 adb。默认 `mcp.sh` 会启动服务且输出授权头，普通 `status` 会刷新 adb 转发和手机令牌，不能作为日志采集入口。分享诊断只保留机型、版本、状态和错误类型。

| 现象 | 核实与处理 |
|---|---|
| Cursor 已退出，Dock 仍显示“正在后台运行” | 手机工位不依赖 Cursor。用 `ps` 核对真实进程，再用 `lsappinfo list` 检查 Cursor 条目的 `exited-with-subordinates` 与 `relatedCoalitionPIDs`；开发工具启动后遗留的网关、adb 或设备发现进程可能仍被 macOS 关联到它。PPID 为 1 或 `Setsid` 不足以证明已解除应用归属。只停止核实过身份且获准退出的进程，不按名称批量杀 adb；菜单栏应用仍运行时可能重新启动连接服务。清理后分别复查进程和应用记录，不能把 Dock 提示等同于 Cursor worker。现场证据与待修项见 [2026-10-18 记录](history/mac-app.md#2026-10-18-cursor-退出后的后台归属排查) |
| 网关未就绪／手机远程已连接但电脑未连接 | 手机与电脑各自连接中继，手机在线不能证明电脑网关已运行。先查 `status --safe` 是否连接被拒绝；本轮修复让 App 专属状态监听在订阅前启动网关，旧安装包仍需重新构建替换。构建与替换步骤见 [Mac 文档](mac-app.md) |
| 认证失败 | 核对两端地址与 SPKI、手机/电脑角色令牌是否放反；证书或凭据变更必须同步两端，不关闭鉴权排障 |
| 远程离线 | 检查手机 MCP 与远程开关、默认网络和中继状态；配置已保存不等于往返已确认，忙碌时的确认中也不等于离线 |
| 升级后仍是长轮询 | 核对实际 Android 与中继版本；Android 69 仅在能力接口明确 404 后回退，最长 5 分钟再探测。代理错误路由也可能返回 404，不能仅凭回退判断服务器版本；见 [控制协议](history/remote-control.md#通道与兼容) |
| 支持 control-v1 但手机未连上 | controlProtocol 只表示服务端能力，另查 controlConnected 和新会话是否稳定；核对手机角色认证、SPKI、默认网络，以及代理是否转发控制路径的 Upgrade。认证、TLS 和网络失败不自动降级 |
| 通知或剪贴板仍按原频率查询 | 本地通道优先时不会建立远程事件连接；远程时核对 Mac 32、主题开关、已有内容会话与手机权限，剪贴板还要求现有 Shizuku 服务支持变化监听。订阅受理不等于主题接受；false 时继续轮询，不为验证强开功能或接收正文 |
| 投屏正常但事件连接失败 | 屏幕、控制与事件使用不同路径，分别核对代理 Upgrade。只放行屏幕路径不足；保留原凭据与来源校验，不用重新配对解决代理错误 |
| Mac 更新后远程持续“确认连接中” | 若新版 `phone-relay-keychain get` 与 SecurityAgent 等待系统授权，用户须在本机完成钥匙串访问提示；不要把密码或凭据发到聊天，不重新配对或关闭钥匙串保护。授权后核对 `status --safe` 的远程在线与实际只读调用；服务器升级前先通过旧中继兼容验收 |
| Shizuku 不可用 | `./scripts/shell.sh --status` 只查询；按原因区分未安装、未运行、未授权和身份不符。非 root 手机重启后须重新启动 Shizuku |
| shell 结果未知 | `./scripts/shell.sh --job-status <原编号>`；`result_unknown` 或记录缺失时核对实际效果，不生成新编号重做 |
| 远程终端能显示提示符，但每次输入都“应答未确认” | Mac 42 及以前把终端创建与输入、缩放、关闭复用了同一个链路操作编号，手机会拒绝冲突请求；创建回执也仍按旧格式判断。更新 Mac 客户端后重新打开终端；已有会话先按原编号查询，不重发旧输入。机制见 [远程交互终端](remote-ops.md#远程交互终端) |
| APK 已安装但服务未恢复 | `./scripts/install-apk.sh --status <原编号>`，分别检查 `verified`、`completed` 与恢复记录。手动打开不算自动恢复验收通过 |
| 手机自更新后远程队列阻塞 | 先核对本地实际版本、原安装任务与中继在途回执；2026-10-03 升级到 60 后曾有 running 回执缺少结果。由部署侧在获批窗口停止同一持久服务、备份完整状态并恢复兼容版本，旧请求保留为 unknown，再查询原任务。不要重新安装、清空回执或退回内存中继；分别记录手机自动启动与经中继恢复后的远程验收 |
| 截图下载中断 | 在 Mac 继续下载上次截图，按原 UUID 查询；已保存但清理未确认时只重试清理，不重拍 |
| 中继 410 | 原操作结果已过期、结果未知或会话已过期；不能把 410 当作重新执行的许可。新操作先取服务端会话代号 |
| 中继 429 | 只有带 `X-Phone-Station-Not-Queued: 1` 才按原编号有界等待；没有该头则停止并核实 |
| 中继存储错误或重启失败 | 保留状态目录、配置和证书；核实磁盘、目录权限、单实例锁、损坏回执与兼容版本。不能删除状态目录“重置”排障 |
| mDNS 可见，但无线连接报 No route to host | 先核对系统本地网络权限、实际网卡路由和手机到电脑的可达性；不能只因手机路由经过 VPN 就认定是 VPN 故障。若 adb 列表为空，核实服务身份并在连接修复范围内重启旧 adb，由手机工位再连接；已有在线设备时不要自动重启共享服务。2026-10-25 重启旧 adb 后恢复，VPN 恢复后仍在线；底层原因未定位，见 [连接恢复记录](history/validation.md#2026-10-25-启动连接恢复与本地心跳) |
| 无线配对报 protocol fault | 使用 mDNS 地址；不要用手机页上的 VPN 地址 `172.19.0.1`，路由不能走 `utun*`，已有在线设备不要重复连接 |
| 系统反复弹出「无线调试已连接」 | 同一无线端口被连了两次，后一次会挤掉前一次；或者 adb 37 解析带空格的 `(2)` 实例名时 abort，服务退出后菜单栏又重连。不要在已有在线设备时再手动 `adb connect`。菜单栏和 `connect.sh` 发现期间已经在线就不再连接；adb 服务需由它们以 `ADB_MDNS=0` 和 `ADB_MDNS_AUTO_CONNECT=0` 启动。仍在循环时退出菜单栏应用，重新构建安装后再连一次 |
| Wi-Fi 短断后不再自动重连 | 旧端口仍在广播，TCP 能接通但 `adb connect` 只回没有路由或拒绝原因的 `failed to connect`。Mac 34 及以前把这当成尚未配对，暂停自动重连。Mac 35 起，这次已经连上过就继续重连；本机已有无线配对记录时，这次还没连上过也不再因此停下。没找到之后按 5、15、30、60 秒自己再找，手机回到同一局域网会被发现。手机点「恢复使用」后远程重新在线，也会再找一次。同一次 `connect.sh` 会再试同一 IP 的其余端口，连上就停 |

公网服务的日志只应包含启动和错误类型。授权头、钥匙串输出、服务器环境文件、任务正文、剪贴板与通知内容不进入诊断附件。真实生产核查与隔离实例验收是两件事；[check-relay](history/relay-contract.md#隔离实例检查) 会模拟手机并重启目标，只能指向专用测试实例。
