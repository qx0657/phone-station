# MCP 客户端权限

Mac 19 的本机网关支持独立客户端令牌。适合把读取文件的客户端与可修改文件、执行 shell 的客户端分开。现有 Mac App 和 `mcp.sh call` 继续使用主令牌；已有客户端不会自动换令牌。新令牌只接受本机 `http://127.0.0.1:18765/mcp`，由网关鉴权后再选择 adb 或远程通道，手机和公网中继不认识这些令牌。

```bash
./scripts/mcp.sh clients create '资料读取' status,files.read
./scripts/mcp.sh clients create '文件整理' status,files.read,files.write
./scripts/mcp.sh clients list
./scripts/mcp.sh clients revoke <list 返回的编号>
```

创建结果包含地址、编号、权限和一次性显示的 `token`；将其配置为该客户端的 `Authorization: Bearer <token>`。不要把结果发到日志或仓库。名称不可重复；遗失令牌时撤销旧编号再创建。`list` 不输出令牌或摘要。以上命令不连接手机、不启动网关；需要已经构建新版网关，正在运行的旧网关需随 Mac 更新后重启才能支持此能力。

| 权限 | 允许的能力 | 边界 |
| --- | --- | --- |
| `status` | 设备、控件、通知同步与 Shizuku 状态 | 不含剪贴板、通知正文、任务输出，也不操作控件 |
| `files.read` | 文件策略、存储概况、列目录、stat、读文本/字节、搜索 | 适用于手机 MCP 已开放的全部普通文件；不是指定目录授权 |
| `files.write` | 创建目录、写入/追加/替换/补丁/截断、复制/移动、删除文件与目录 | 各工具原有版本校验、路径规则仍有效；通常与 `files.read` 一起授予 |
| `shell` | shell exec/start 与 operation status | 可读所有已知编号的短期任务结果。shell 本身拥有 Shizuku 的 shell/root 系统能力，不是受文件目录限制的沙箱 |

四项独立授予，没有隐式继承或通配权限。客户端可初始化、ping、列出自己可用的工具；不允许未知 RPC 方法。`station_file_open` 会打开手机界面，不属于文件读写；剪贴板、手机通知接收/配置、提醒、截屏、手电筒与亮屏目前仅主令牌可用。以后增加的工具默认拒绝，必须显式加入网关授权表。

网关按请求重新读取 `clients.json`（用户配置目录 `Phone Station` 下），最多 128 个客户端。文件只保存随机 256 位令牌的 SHA-256 摘要、名称、权限、编号和创建时间，目录 0700、文件 0600；增删使用文件锁、临时文件、fsync 与原子替换，跨进程操作不会互相覆盖。损坏或未知版本的授权文件使客户端请求失败，不回退到主权限。撤销对下一次鉴权生效，已经接收或排队的请求不会自动取消；撤销也不会撤回已写文件。

一次批量调用先校验全部项：重复字段/编号、未授权工具或未知方法使整批失败，尚未转发任何项。`tools/list` 在两条通道均过滤；直接猜工具名也无法越权。`/__status`、`/__events`、`/__remote-call` 仅主令牌可用。

这层隔离针对只拿到客户端令牌的调用方。能读取本机主配置、直接运行 owner CLI、使用 adb 或控制公网中继的人不受此层限制；不要同时把主令牌交给受限客户端。此轮没有自动签发真实令牌、更换用户配置或重启正在运行的网关。

离线测试覆盖创建/并发保存/权限位/撤销、损坏文件关闭访问、批次预检、工具列表、未知工具、文件打开与任务输出隔离、主入口拒绝及本地/远程两种路由。
